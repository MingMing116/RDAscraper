# RDAscraper 사용 안내

보도자료에서 제목과 핵심어를 추출하고 관련 뉴스를 검색·검수하여 엑셀 XLSX·CSV·PDF로 저장하는 Windows 프로그램입니다. **압축을 풀고 `RDAscraper.exe`를 실행하면 됩니다.** Python·Node.js·Go 또는 별도 OCR 프로그램을 설치할 필요가 없습니다.

## 실행 환경

Windows 10/11 64비트와 Edge 또는 Chrome을 사용합니다. 독립 창을 열 수 없으면 기본 브라우저로 화면을 엽니다. 문서 분석·한국어/영어 OCR·작업 보관·PDF 생성은 PC에서 처리합니다. 분석용 중계 서버, 클라우드 브라우저, 계정 가입이 없습니다.

뉴스 검색과 기사 수집에는 인터넷이 필요합니다. PC가 검색·언론 사이트에 요청하며, 설정된 HTTP(S) 프록시가 있으면 그 경로를 사용합니다. 화면 주소 `127.0.0.1`은 이 PC를 뜻합니다. EXE가 화면과 기능을 제공합니다.

## 창 크기에 맞춰 조절되는 화면

**Noto Sans KR Bold**를 프로그램에 포함하여 별도 글꼴 설치 없이 표시합니다. 이전 배포보다 화면 전체를 조금 줄이고, 실제 창 너비에 맞춰 글자·메뉴·간격이 조절되도록 했습니다.

| 상단 글자 크기 선택 | 기본 글자 | 용도 |
| --- | --- | --- |
| 보통 | 18–19px | 처음 실행할 때의 기본값 |
| 크게 | 20–21px | 글자와 입력 요소를 함께 확대 |
| 아주 크게 | 22–23px | 가장 큰 화면 글자 설정 |

각 범위 안에서 좁은 창은 작게, 넓은 창은 크게 표시합니다. 최대화 버튼의 상태를 직접 감지하는 방식이 아니라 **브라우저 안의 실제 화면 너비**를 기준으로 조절합니다. 창을 줄이거나 좌우로 나누어 써도 같은 규칙이 적용됩니다. 가로 공간이 부족하면 메뉴와 입력 영역의 배치가 바뀌고 기사 표는 가로로 스크롤할 수 있습니다. 보조 설명은 최소 15px를 유지합니다.

선택한 글자 크기는 이 PC의 브라우저에 기억합니다. 다른 브라우저나 PC에서는 각각 선택하세요. 기존 화면에서 선택했던 크기도 해당 단계로 유지됩니다. [글자 크기와 업데이트 안내](docs/APPEARANCE_KO.md)

검수 목록 PDF는 본문 13pt, 날짜·매체 등 정보 12pt, 문서 제목 26pt, 기사 제목 18pt로 표시하며 Noto Sans KR 계열의 굵은 글꼴을 내장합니다. 화면의 글자 크기 선택은 PDF에 적용되지 않습니다. 화면과 PDF에는 버전 배지를 표시하지 않습니다.

## 새 파일인데 글자가 달라지지 않을 때

앞서 실행한 프로그램이 남아 있으면 새 파일을 눌러도 이전 화면을 볼 수 있습니다. 이전 64.1.1에서는 기존 엔진을 다시 여는 방식이었습니다. 이번 수정본에서는 이전 버전을 발견하면 기존 화면과 교체 안내창을 함께 엽니다.

1. 기존 화면에서 **작업 저장**을 눌러 JSON 파일을 내려받습니다.
2. 기존 화면 상단 **종료**를 누릅니다. 창의 X만 닫으면 엔진이 남아 있을 수 있습니다.
3. 교체 안내창의 **확인**을 누릅니다. 기존 엔진 종료를 확인한 뒤 새 화면이 열립니다.
4. 필요하면 **작업 불러오기**로 저장한 JSON을 엽니다.

교체를 진행하지 않으려면 안내창에서 **취소**를 누릅니다. 기존 작업을 강제로 종료하거나 저장본을 삭제하지 않습니다. 기존 엔진이 응답하지 않는 경우의 절차는 아래 실행 오류 안내에 있습니다.

## 네 단계로 사용하기

1. **자료 입력**: HWP/HWPX/PDF/TXT 또는 PNG/JPG/WEBP/BMP를 선택하거나 제목과 본문을 입력합니다.
2. **핵심어와 기간 확인**: 추출한 제목·본문·핵심어를 확인하고 검색 기간을 정합니다. 검색어가 검색 서비스에 전달되므로 공개할 수 있는 표현인지 확인합니다.
3. **기사 검수**: 기사 행을 눌러 선택·해제하고 제목을 눌러 원문을 엽니다. ‘판별 근거 보기’에서 날짜와 확보한 본문을 확인합니다. 누락된 기사는 URL로 직접 추가할 수 있습니다.
4. **결과 저장**: 선택한 기사를 엑셀 XLSX, 한글 CSV, 검수 목록 PDF로 저장합니다. PDF는 기사 번호순이며 선택에서 빠진 번호를 다시 매기지 않습니다. 기사 번호는 정렬·필터 변경 후에도 유지됩니다.

진행 중인 작업은 **검색 중단** 또는 **분석 중단**으로 멈출 수 있습니다. 제목은 제목 칸에서, 본문은 **추출 본문 확인 · 수정**에서 수정하세요.

## 엑셀·CSV·PDF 저장

| 저장 버튼 | 저장되는 내용 |
| --- | --- |
| **엑셀 XLSX** | 행 높이 30pt, 고정 열 너비, 줄바꿈 해제, 첫 행 고정과 필터를 적용한 통합문서. 긴 내용은 셀을 선택해 전체 확인 |
| **한글 CSV** | 셀 안의 줄바꿈·탭·연속 공백을 정리한 데이터 파일. 일정한 행 높이는 XLSX 사용 |
| **검수 목록 PDF** | 선택 기사 정보와 발췌문을 기사 번호순으로 저장 |

CSV 형식에는 행 높이·글꼴·열 너비 설정을 저장할 수 없습니다. XLSX는 기존과 같이 모든 행을 30pt로 유지합니다.

검수 목록 PDF는 기사일·매체·제목·발췌문·원문 링크를 정리한 파일입니다. 기사 원문 전체와 사진은 기사 링크를 눌러 확인하세요. PDF 생성에는 별도 인쇄 브라우저를 실행하지 않습니다.

PDF의 기사 번호는 기존 번호를 유지합니다. 예를 들어 1~24번 중 8·14번을 선택하지 않았다면, 22건이 **1~7, 9~13, 15~24번** 순서로 저장됩니다. 누락된 번호를 채우기 위해 다른 기사의 번호를 바꾸지 않습니다.

[검수 목록 PDF 상세 안내](docs/REVIEW_PDF_KO.md)

## 기사 본문을 다시 가져오거나 보완하기

1. 기사 행의 **판별 근거 보기**를 열고 확보한 본문과 출처·확인 상태를 확인합니다.
2. **본문 다시 가져오기**로 새 수집을 시도합니다. 접근 제한이나 이미지·스크립트 중심 기사에서는 여전히 본문을 확보하지 못할 수 있습니다.
3. 원문에서 직접 확인한 내용을 넣으려면 **본문 직접 보완**을 누르고 입력한 뒤 **수정 내용 저장**을 누릅니다.

직접 보완한 본문은 자동 수집과 구분해 **사용자 보완**으로 기록하며, 원문 확인 완료로 처리하지 않습니다. 이 내용은 화면 검수와 작업 JSON에 보관됩니다. 검수 목록 PDF는 기사 정보와 발췌문을 저장하며, 직접 보완한 본문 전체를 출력하지 않습니다.

## OCR 선택

| 선택 | 동작 |
| --- | --- |
| 자동 | 이미지와 텍스트가 거의 없는 PDF 페이지에 OCR 적용 |
| PDF 전체를 OCR로 읽기 | PDF를 화면에 보이는 글자로 다시 인식. 선택 후 파일을 다시 분석 |
| 사용 안 함 | 문서 안의 텍스트만 읽기 |

파일은 최대 25MB, PDF 읽기는 최대 100쪽, OCR은 문서당 최대 20쪽, 이미지는 최대 4천만 화소입니다. 흐린 사진·손글씨·복잡한 표는 인식이 부정확할 수 있습니다. 제목·날짜·핵심어를 확인한 뒤 검색하세요. 한국어와 영어 인식 데이터는 프로그램에 포함됩니다.

## 작업 저장과 삭제

상단 **저장 설정**에서 **이 PC에 작업 자동 저장**을 선택합니다. 기본값은 켜짐이며 설정은 이 PC에 보관됩니다. 자동 저장본은 암호화된 보관함이 아니므로 공용 PC에서는 필요에 맞게 해제하세요.

- **자동 저장 켜짐**: 브라우저 저장소와 `%APPDATA%\RDAscraper\last-project.json`에 작업을 보관합니다.
- **자동 저장 끄기**: 자동 저장본과 실행 로그를 지우고 이후 작업 자동 저장을 중지합니다. 현재 화면은 유지됩니다.
- **자동 저장본 · 실행 로그 삭제**: 저장본과 실행 로그를 지우고 자동 저장을 끕니다. 현재 화면의 작업은 유지됩니다.
- **작업 저장**: 현재 작업을 JSON으로 다운로드합니다. **작업 불러오기**로 다시 엽니다.
- **RDAscraper 로고 클릭**: 진행 중 작업을 중단하고 처음 화면으로 초기화합니다. 자동 저장 설정 자체는 바꾸지 않습니다.

원본 문서와 이미 다운로드한 JSON·XLSX·CSV·PDF는 위 기능으로 삭제되지 않습니다. 로그는 삭제 후에도 실행·오류에 따라 최소 기록이 다시 생길 수 있습니다. 자세한 범위는 [개인정보와 로컬 보관](PRIVACY.md)을 참고하세요.

이전 작업 JSON도 불러올 수 있습니다. 불러온 기사의 확인 완료 표시는 미확인 상태로 바뀌므로 원문을 다시 확인하세요. 형식이 잘못된 작업 파일은 불러오지 않습니다.

종료할 때는 상단 **종료**를 누르세요. 창의 X만 닫으면 로컬 엔진이 남아 있을 수 있습니다. 다시 EXE를 실행하면 기존 화면을 엽니다.

## ‘이미 실행 중인 프로그램이 응답하지 않습니다’가 나타날 때

1. 떠 있는 **RDAscraper 실행 확인** 오류창을 모두 닫습니다.
2. Win+R을 누르고 `%APPDATA%\RDAscraper\address.txt`를 입력합니다. 파일에 적힌 `http://127.0.0.1:…` 주소를 Edge 또는 Chrome에서 엽니다.
3. 화면이 열리면 **작업 저장**으로 JSON을 내려받은 뒤 상단 **종료**를 누릅니다. 창의 X만 닫는 것으로 끝내지 마세요.
4. 새 `RDAscraper.exe`를 실행합니다. 필요하면 방금 저장한 JSON을 **작업 불러오기**로 엽니다.

주소 파일이 없거나 화면이 계속 응답하지 않는다면 작업 관리자에서 **RDAscraper.exe만** 종료한 뒤 새 EXE를 실행합니다. 강제 종료 시 저장하지 않은 변경은 사라질 수 있지만, 기존에 저장한 JSON·XLSX·CSV·PDF를 지울 필요는 없습니다. 브라우저나 다른 프로그램을 종료할 필요도 없습니다.

수정본은 이전 엔진의 응답을 버전과 별개로 확인합니다. 이전 버전 엔진이 정상인 경우 기존 화면과 작업 저장·종료·확인 안내를 엽니다. 확인 후에는 이전 엔진의 잠금이 해제되는지 기다렸다가 새 프로그램을 시작합니다. 자세한 원인과 대응은 [시작 오류 해결](docs/STARTUP_FIX_KO.md)에 있습니다.

## 화면 또는 기사 수집이 열리지 않을 때

- 예전 즐겨찾기의 고정 주소 대신 EXE로 시작합니다. 실행할 때 사용하는 포트가 달라질 수 있습니다.
- 실행 기록은 `%APPDATA%\RDAscraper\RDAscraper.log`에서 확인합니다. 로그는 크기를 제한하고 원문 주소의 경로·검색 문자열 등 민감한 내용을 줄여 기록합니다.
- 실행 주소를 저장할 수 없다는 안내가 나타나면 안내된 저장 위치의 쓰기 권한·저장 공간을 확인한 뒤 다시 실행합니다. 주소를 저장하지 못한 상태를 정상 시작으로 표시하지 않습니다.
- 프록시 사용 중 수집이 실패해도 직접 접속으로 우회하지 않습니다. 접근 제한된 기사에는 수집 실패가 표시될 수 있습니다.

## 배포와 검증

일반 사용자는 GitHub 저장소의 **Releases**에서 Windows 실행용 ZIP을 내려받습니다. GitHub 웹페이지가 EXE를 실행하는 것은 아닙니다. 외부망 PC가 GitHub 다운로드를 허용한다면 그 PC에서 받아 실행할 수 있습니다. 조직의 다운로드·실행 제한을 해제하거나 우회하는 기능은 없습니다.

65.3.1은 원본 업무자료명과 배포 안내를 정리한 배포입니다. 저장 메뉴를 **엑셀 XLSX · 한글 CSV · 검수 목록 PDF**로 정리한 배포입니다. 검수 목록의 번호순 정렬, XLSX 행 높이 30pt, CSV, 글자 크기 설정, 작업 교체 절차, 로컬 OCR과 398개 매체 기준표는 유지합니다.

**이번 변경의 Windows 실기기 실행은 확인하지 못했습니다.** 실제 수행한 검사와 남은 항목은 [검증 기록](docs/VALIDATION_KO.md)에 구분합니다. 실행파일에는 코드 서명이 없습니다.

뉴스 검색은 검색 서비스 제공 범위와 사이트 변경에 영향을 받습니다. 로그인·접근 제한·스크립트 실행에 의존하는 기사에서는 본문 수집에 실패할 수 있습니다. 기사 제목을 눌러 원문을 확인하세요. 암호화 HWP는 지원하지 않습니다.
