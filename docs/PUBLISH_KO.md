# GitHub 공개 배포 방법

배포 저장소는 https://github.com/MingMing116/RDAscraper 입니다. Windows 실행용 ZIP은 자동 검사가 성공한 뒤 저장소의 Releases에서 제공합니다. 아래는 이후 업데이트와 Release 게시 절차입니다.

이번 배포는 **65.3.1**입니다. 매체 기준표의 원본 업무자료명을 제거하고 수정 소스로 EXE를 다시 빌드했습니다. 결과 저장을 **엑셀 XLSX · 한글 CSV · 검수 목록 PDF**로 정리했습니다. 검수 목록은 기존 기사 번호의 오름차순을 유지하며 선택하지 않은 번호를 다시 매기지 않습니다. XLSX 행 높이 30pt와 CSV 출력도 유지합니다. [검수 목록 PDF 상세 안내](REVIEW_PDF_KO.md)

기사 원문 PDF와 보조 추출 본문 PDF, 원문 인쇄용 브라우저 실행 경로 및 PDF 병합 모듈은 제거했습니다. 검수 목록 PDF는 별도 인쇄 브라우저를 시작하지 않고 로컬에서 생성합니다.

Windows 자동 빌드·실행파일 시험 결과는 [Actions](https://github.com/MingMing116/RDAscraper/actions)에서 해당 배포 커밋의 실행 기록으로 확인합니다. 사용자 PC의 실제 공개 뉴스 검색은 별도 확인 범위입니다. 제작환경 사전 검사 범위는 [검증 기록](VALIDATION_KO.md)에 구분합니다.

## 1. 소스 올리기

배포된 GitHub 소스 ZIP을 풀고 `RDAscraper` 폴더 안의 내용을 새 저장소의 루트에 올립니다. `README.md`, `go.mod`, `web`, `tests`, `.github`가 저장소 루트에 있어야 합니다. ZIP 파일 자체만 Code 화면에 올리면 자동 검사와 빌드가 실행되지 않습니다.

새 소스 묶음만 사용하세요. 과거 원본 보도자료·실제 작업 JSON·개발 로그·이전 Git 이력과 사용자가 제공한 실제 기사 PDF·검수 목록 PDF·CSV·XLSX는 공개 소스에서 제외합니다. 시험에는 합성 자료만 사용합니다. 공개 소스의 재사용 라이선스는 권리자가 정할 수 있도록 별도 지정하지 않았으며, 기존 의존성 라이선스 고지는 유지했습니다.

### 과거 Git 이력과 구분

이 ZIP은 현재 공개 파일만 담은 소스 묶음이며 `.git` 이력을 포함하지 않습니다. 새 빈 저장소에 이 소스만 올리면 과거 작업 파일을 함께 전송하지 않습니다. 기존 저장소의 커밋·브랜치·태그·Release 첨부 파일에는 별도로 정보가 남을 수 있습니다. 이 묶음으로 파일을 덮어쓰는 것만으로 기존 이력은 지워지지 않습니다. 공개 전에는 초기 README 커밋만 있던 저장소를 확인한 뒤 정리한 소스를 게시했습니다. 이후의 커밋·브랜치·태그·Release는 업데이트마다 별도로 확인해야 합니다.

## 2. 자동 검사 확인

기본 브랜치 `main` 또는 `master`에 올리거나 Actions의 **Verify and build**를 실행합니다. Linux의 기능·보안·OCR·실제 브라우저 검사가 통과하면 Windows에서 엔진 시험, EXE 빌드, 실제 Chromium 통합 시험을 수행합니다.

해당 커밋의 Actions 검사 결과를 확인하세요. 자동 시험의 뉴스 응답은 합성 자료이며 사용자 PC에서 공개 뉴스 검색·원문 확인·검수 목록 PDF 동작을 확인하는 절차와 구분합니다. Actions가 생성하는 `RDAscraper-Windows-x64` 산출물에는 실행용 ZIP과 SHA256SUMS가 들어 있습니다.

일반 CI의 뉴스 응답은 합성 자료입니다. 실제 공개 뉴스는 Actions의 **Windows live news verification**을 별도로 수동 실행합니다. 이 workflow는 Windows EXE와 설치된 Edge를 사용하고, `RDAscraper-native-Windows-live-evidence` 산출물에 실제 성공·실패 기록을 남깁니다. 스크립트가 준비되어 있다는 사실만으로 시험이 통과한 것은 아닙니다.

직접 Windows PC에서 확인하려면 개발용 의존성 설치(`npm ci`)와 EXE 빌드 후 다음 명령을 실행합니다.

```powershell
.\tests\windows_e2e.ps1 -Binary dist/RDAscraper.exe -Headed
```

`tests/artifacts/live_browser/validation.json`에서 Windows 실행 여부와 바이너리 해시, 검색·원문 확인·PDF 저장 결과를 확인합니다. `-SyntheticOnly`는 별도 합성 회귀시험이므로 실제 뉴스 검증을 대신하지 않습니다. 실패한 검색 다음의 원문·PDF 단계는 미확인으로 기록합니다. 이 개발 시험에 필요한 Node·Playwright는 일반 사용자 설치 요건이 아닙니다.

Windows 확인에는 다음 항목을 포함합니다.

- 공개 보도자료 입력 → 실제 뉴스 검색 → 원문 확인 → 검수 목록 PDF 저장
- 검수 목록 PDF의 기사 번호 오름차순과 선택하지 않은 번호 유지
- 기사일·매체·제목·발췌문·원문 링크, 긴 제목·문단과 한글 표시
- XLSX의 행 높이 30pt, CSV의 셀 안 줄바꿈 정리와 한글 표시
- 저장 메뉴 세 가지 표시, 이전 원문·추출 본문 PDF 메뉴 제거
- 기존 JSON 불러오기, 작업 저장과 정상 종료·재실행

기존 자동 시험 스크립트에 해당 검사가 모두 포함되었다고 가정하지 말고 [현재 검증 기록](VALIDATION_KO.md)의 실제 실행 범위와 구분합니다.

## 3. Release 만들기

원하는 태그로 Release를 만들고 검증된 Windows 실행용 ZIP과 `SHA256SUMS.txt`를 첨부합니다. 제3자 고지는 현재 `docs/THIRD_PARTY.md`와 `web/licenses/`의 구성요소별 자료를 사용합니다. 빌드 버전은 파일 메타데이터와 변경 기록에 남으며 사용자 화면에는 표시하지 않습니다.

제공된 EXE는 새 소스로 교차 빌드한 파일입니다. CI에서 다시 빌드한 파일을 배포할 경우 CI가 생성한 해시를 함께 배포하고, 서로 다른 빌드의 해시를 혼용하지 마세요. SHA-256은 다운로드 파일의 일치 확인용이며 코드 서명을 대신하지 않습니다.

## 4. 이전 배포에서 업데이트하기

기존 오류창을 모두 닫고 새 EXE를 실행합니다. 이전 버전이 실행 중이면 기존 화면과 교체 안내창이 함께 열립니다. 기존 화면에서 **작업 저장 → 상단 종료**를 마친 뒤 교체 안내창의 **확인**을 누르면 새 프로그램이 시작됩니다. 교체를 보류하려면 **취소**를 누릅니다.

창의 X만 닫은 상태에서는 이전 엔진이 남아 있을 수 있습니다. 이전 64.1.1은 새 EXE를 눌러도 먼저 실행된 엔진의 화면을 다시 열었으므로 글꼴 수정이 보이지 않을 수 있었습니다. 새 화면에서는 상단 **글자 크기**에서 **보통 / 크게 / 아주 크게**를 선택할 수 있습니다. [화면 변경 확인](APPEARANCE_KO.md)

기존 화면에 접근할 수 없는 경우 `%APPDATA%\RDAscraper\address.txt`의 주소를 먼저 확인합니다. 그래도 응답하지 않으면 작업 관리자에서 RDAscraper.exe만 종료하고 새 파일을 실행합니다. 저장하지 않은 변경은 사라질 수 있으므로 가능한 경우 JSON 저장을 먼저 합니다. 프로필 폴더나 저장된 JSON·XLSX·CSV·PDF를 삭제하지 않습니다. [상세 복구 절차](STARTUP_FIX_KO.md)

## 5. 사용자가 실행하기

인터넷 사용이 허용된 외부망 PC에서 저장소의 Releases를 열어 실행용 ZIP을 받습니다. 압축을 풀고 `RDAscraper.exe`를 실행합니다. 사용자 PC에 Python·Node.js·Go를 설치할 필요가 없습니다. 프로그램 화면은 해당 PC의 Edge 또는 Chrome에서 열립니다. 검수 목록 PDF는 프로그램이 PC에서 직접 생성합니다.

GitHub는 다운로드 경로입니다. 프로그램은 사용자의 PC에서 실행되고 화면은 해당 PC의 브라우저에서 열립니다. GitHub Pages나 GitHub 웹 화면에서 EXE를 실행하는 구조가 아닙니다. 기관의 파일 다운로드·실행·망간 전송 정책은 그대로 적용됩니다.

실제 뉴스 검색과 기사 수집은 DNS, 프록시, 사이트 접근 정책에 영향을 받습니다. 프로그램은 기관의 정책이나 사이트 접근 제한을 해제하지 않습니다. 이번 배포의 실행 환경·바이너리 해시·검사 범위는 [현재 검증 기록](VALIDATION_KO.md)에 남깁니다. 공개 검증 자료에는 현재 시험·빌드·점검 요약만 포함하며, 사용자 입력 문서의 메타데이터와 과거 내부 검증 기록은 제외합니다.

## 검증 후 자동 게시

`main`에 `[publish-release]`가 포함된 커밋을 푸시하면 `Verify and build`의 Linux·Windows 검사가 성공한 뒤 별도 `Publish verified Windows release` workflow가 그 실행의 Windows ZIP과 SHA-256을 Releases에 게시합니다. 게시 job만 `contents: write`, `actions: read`를 사용합니다. PR·일반 push·수동 후보 빌드는 Release를 게시하지 않습니다. 기존 태그의 Release는 덮어쓰지 않으며 새 버전에서는 workflow의 `RELEASE_TAG`와 표시 버전을 함께 갱신합니다.
