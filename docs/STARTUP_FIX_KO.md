# 실행 오류와 이전 버전 교체 안내

## 화면은 열리지만 글꼴이 바뀌지 않을 때

먼저 실행된 엔진이 남아 있으면 새 EXE를 눌러도 이전 화면이 열릴 수 있습니다. 이전 64.1.1은 정상인 기존 엔진의 화면을 다시 열고 수동 재실행을 안내했습니다. 이것은 새 실행파일의 화면으로 교체됐다는 뜻이 아닙니다.

이번 수정본에서는 이전 버전이 정상 응답하면 기존 화면과 교체 안내창을 엽니다.

1. 기존 화면에서 **작업 저장**으로 JSON을 내려받습니다.
2. 기존 화면 상단 **종료**를 누릅니다.
3. 교체 안내창의 **확인**을 누릅니다. 이전 엔진의 종료를 기다린 뒤 새 화면을 엽니다.
4. 필요하면 **작업 불러오기**로 저장한 JSON을 엽니다.

교체를 진행하지 않으려면 **취소**를 누릅니다. 프로그램이 작업을 자동으로 강제 종료하거나 저장본을 삭제하지 않습니다. 새 화면에는 상단 **글자 크기** 선택이 표시됩니다. Noto Sans KR 굵은 글꼴과 기본 20px 글자를 적용하며 [크기 안내](APPEARANCE_KO.md)에서 세 단계 설정을 확인할 수 있습니다.

## ‘이미 실행 중인 프로그램이 응답하지 않습니다’가 나타날 때

1. **RDAscraper 실행 확인** 오류창을 모두 닫습니다.
2. **Win+R**을 누르고 `%APPDATA%\RDAscraper\address.txt`를 입력합니다.
3. 파일의 `http://127.0.0.1:…` 주소를 복사해 Edge 또는 Chrome에서 엽니다. 이 주소는 현재 PC의 프로그램 화면입니다.
4. 화면이 열리면 **작업 저장**으로 JSON 파일을 내려받은 다음 상단 **종료**를 누릅니다.
5. 새 **RDAscraper.exe**를 실행합니다. 필요하면 저장한 JSON을 **작업 불러오기**로 다시 엽니다.

파일이 없거나 해당 주소에서도 응답하지 않으면 **작업 관리자(Ctrl+Shift+Esc)**에서 **RDAscraper.exe만** 종료하고 새 EXE를 실행합니다. 강제 종료하면 저장하지 않은 변경은 사라질 수 있습니다. 이미 저장한 JSON·CSV·PDF는 삭제하지 않으며, `%APPDATA%\RDAscraper` 폴더를 지우는 초기화도 필요하지 않습니다.

브라우저와 다른 프로그램은 종료할 필요가 없습니다. 작업 중인 RDAscraper가 정상 응답하면 저장 후 화면의 **종료** 버튼으로 끝내세요. 창의 X만 닫아도 로컬 엔진이 남아 있을 수 있습니다.

## 시작 처리의 수정 내용

첨부됐던 오류창은 다른 RDAscraper가 실행 중이라고 판단한 뒤 기존 화면의 응답을 확인하지 못했을 때 표시됩니다. 사용자 PC의 프로세스·로그를 직접 확인한 것은 아니므로 당시 원인을 하나로 단정하지 않습니다. 코드에서 확인하여 수정한 내용은 다음과 같습니다.

| 문제 | 수정 |
| --- | --- |
| 앞서 실행한 엔진이 정상이어도 새 EXE와 버전이 다르면 응답 실패로 판단 | 버전과 별개로 로컬 엔진의 정상 응답 확인 |
| 중복 실행 프로세스가 Windows mutex 핸들을 쥔 채 오류창 표시 | 중복 확인에 사용한 핸들을 즉시 닫음 |
| 기존 엔진이 종료되는 사이에 실행해도 잠금 획득을 다시 시도하지 않음 | 제한된 시작 대기 동안 운영체제 잠금 획득 재시도 |
| 실행 주소 파일 저장 오류를 확인하지 않음 | 주소 파일 저장 실패 시 시작 오류 표시 |
| 이전 버전의 화면을 다시 열어 새 글꼴이 적용되지 않을 수 있음 | 작업 저장·기존 엔진 종료·사용자 확인 후 새 프로그램 시작 |

시작 확인은 로컬 `127.0.0.1` 주소로 제한하며 리다이렉트를 따라가지 않습니다. 응답 크기·상태 코드·정상 응답 내용도 검사합니다. 기존 엔진을 강제 종료하거나 운영체제 잠금을 강제로 빼앗지 않습니다.

Windows mutex는 관련 핸들을 유지하는 프로세스가 있을 때 존재합니다. 모든 관련 프로세스가 끝난 뒤에도 mutex 자체가 계속 남는다는 의미는 아닙니다. 이전 오류창의 프로세스가 핸들을 열어 둔 경우 새 실행에 영향을 줄 수 있어 오류창부터 닫도록 안내합니다.

## 검증 범위

현재 검사 결과는 [검증 기록](VALIDATION_KO.md)에 정리합니다. **이 제작 환경에서는 Windows의 새 EXE 실실행을 아직 확인하지 못했습니다.** 실제 뉴스 검색도 이번에 새로 확인하지 않았습니다. 이전 시작 처리 변경은 [변경 기록](../CHANGELOG.md)에 정리했습니다. Linux 기능시험과 Windows 교차 빌드 결과를 Windows 실기기 실행 성공으로 표시하지 않습니다.
